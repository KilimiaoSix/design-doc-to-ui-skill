# APP Style Candidates

Purpose: candidate visual styles for a design-doc-to-UI workflow. Each style must support four endpoints:

- Web: browser-based responsive web app or mobile web.
- PC: desktop app or desktop-width product interface.
- Mobile: native phone app.
- Tablet: tablet app with expanded layout.

Generation strategy: create one four-panel style board per style. Each board should show Web, PC, Mobile, and Tablet examples for the same product scenario so the style can be evaluated across form factors before being accepted into the catalog.

## Foundation Sources

- Apple Human Interface Guidelines: platform-native hierarchy, navigation, materials, dark mode, and adaptive layouts.
- Material Design 3 / Material 3 Expressive: dynamic color, responsive components, emphasized typography, larger controls, and expressive motion.
- Microsoft Fluent 2: platform-aware layouts, focus, inclusivity, tokens, light/dark/high-contrast theming, and cross-platform UI kits.
- WCAG 2.2: accessibility baseline, including target size, focus visibility, authentication, and contrast-related checks.
- Baymard mobile e-commerce UX research: commerce-specific mobile patterns such as product lists, filtering, galleries, checkout, and order confirmation.
- 2026 app/UI trend research: bento grids, AI-native interfaces, low-stimulus UI, responsible glassmorphism, dark mode, personalization, gamification, and gesture-led experiences.

## Acceptance Rules

For a style to be accepted:

- All four endpoints are represented in the sample board.
- The style is recognizable without relying on labels alone.
- The same visual language is consistent across Web, PC, Mobile, and Tablet.
- UI looks like usable product interface, not poster art.
- Text is minimal and legible; no obvious gibberish or broken UI.
- The style includes usable prompt guidance and negative constraints.
- Accessibility risks are explicitly noted when the style is visually risky.
